# Chapter 10: JWT Authentication

## JWT Authentication
JSON Web Tokens (JWT) provide a stateless, secure format for transmitting user authentication details.

### Structure of a JWT
A JWT is composed of three base64-url encoded parts separated by periods:
1. **Header**: Contains metadata (e.g., algorithm `HS256`, type `JWT`).
2. **Payload**: Houses claims (user email, role, issue date, and token expiry time).
3. **Signature**: Validates that the token was not tampered with. It is generated by hashing the header, payload, and a secret key using the specified algorithm.

### Access Tokens vs. Refresh Tokens
- **Access Tokens**: Short-lived (e.g., 1 hour). Used to authenticate API requests.
- **Refresh Tokens**: Long-lived (e.g., 7 days) and stored in the database. Used to request new access tokens without prompting the user to re-enter credentials.

### Authentication & Authorization Flow
1. Client logs in with credentials -> Backend generates JWT and Refresh Token.
2. Client stores tokens and attaches the JWT to the `Authorization` header (`Bearer <token>`) for protected requests.
3. The server intercepts requests, parses the header, extracts the JWT, validates its signature and expiration, and establishes user details in the security context.
